# Monit 二次开发指南

> 适用版本：M23（2026-08-31）· 许可证：MIT · 技术栈：Laravel 12 + PHP 8.3 + Tailwind v4 + Vite
>
> 本文档面向需要深度定制 Monit 的开发者，覆盖：整体架构、请求生命周期、目录地图、
> 核心数据流、全部扩展点，以及 6 个常见二开场景的实操示例。

## 1. 整体架构

Monit 是一个「自托管网站监控与分析」单体应用（非微服务），按职责分层：

```
                    ┌──────────────────────────────────────────┐
   被监控网站  ────▶ │  像素采集层 routes/track.php（无中间件）      │
   (monit.js SDK)   │  PixelTrackController → PixelTracker 服务   │
                    └───────────────┬──────────────────────────┘
                                    │ 解析/预检/分流(advanced|lightweight)
                                    ▼
   ┌────────────┐   ┌──────────────────────────────────────────┐
   │ 采集 SDK     │   │  存储层：websites / visitors / sessions /  │
   │ public/assets│   │  events / lightweight_events / goals ...   │
   │ /pixel/monit.js│ └───────────────┬──────────────────────────┘
   └────────────┘                     │ 聚合查询
                    ┌───────────────┴──────────────────────────┐
   用户浏览器 ─────▶ │  Web 层：StatsController + StatisticsService │
   (Blade+Tailwind) │  30+ 统计维度 / 回放 / 热图 / 目标            │
                    └───────────────┬──────────────────────────┘
   第三方系统 ─────▶ │  API 层：routes/api.php（API Key 认证）        │
                    │  REST v1 + admin-api                        │
                    └──────────────────────────────────────────┘
```

关键设计决策：

| 决策 | 理由 |
|------|------|
| 采集路由独立文件（无 web 中间件组） | 高频请求免 Session/Cookie 开销（M23） |
| pixel_key → Website 查询缓存 60s | 每请求 1 次 DB 查询降为缓存命中；Website/User saved 钩子联动失效 |
| 双采集模式（advanced / lightweight） | 隐私敏感/超高频站点可退化为无访客标识的纯聚合 |
| settings 表 K-V + `App\Support\Settings` 静态门面 | 全部平台配置后台热更（含品牌/主题/ICP），进程内静态缓存 + Cache |
| 落地页模板机制 `themes/{theme}/` | 后台切换模板零代码；新增主题只建目录即可 |
| 统计口径：源数据按 ISO 周存 dow，展示按 locale | sqlite/mysql 方言差异在入库前抹平（M22） |

## 2. 请求生命周期

以一次「统计页访问」为例（完整链路）：

```
GET /stats/{website}
 → bootstrap/app.php（中间件装配：web 组 + CheckMaintenance + EnsureUserActive）
 → routes/web.php 命中 StatsController@index（auth 中间件保护）
 → Controller 校验权限（WebsitePolicy，Gate 注册在 bootstrap/app.php）
 → StatisticsService::range($website, $start, $end)（缓存键 = website+range）
 → Blade 视图 resources/views/stats/index.blade.php（@extends layouts.app）
 → 品牌注入：parts/brand_head（favicon/主色/自定义HEAD）+ parts/brand_footer_scripts
```

以一次「像素上报」为例（性能关键路径）：

```
POST /pixel-track/{pixel_key}
 → routes/track.php（无中间件；CSRF 由 bootstrap validateCsrfTokens except 豁免）
 → PixelTrackController::__invoke
    ├─ Cache::remember('pixel.website.{key}', 60s)  ← M23 查询缓存
    └─ PixelTracker::handle($website, $request)
         ├─ passesPreChecks：禁用/host/爬虫/IP排除/用户状态/配额
         ├─ 分流：isLightweight() → handleLightweight()
         │        否则           → handleAdvanced()（会话/访客归因）
         └─ incrementUsage（月配额/24h/7d 计数器 DB::raw 原子自增）
 → 响应恒 204 + CORS *（不泄露内部状态）
```

## 4. 核心数据流

### 4.1 事件写入（advanced 模式）

```
payload(type=data) → 匹配/创建 WebsiteVisitor（uuid 二进制主键，无 Cookie）
 → 会话判定（monit.pixel.session_timeout=1800s 空闲切新会话）
 → VisitorSession 归因（来源渠道/UTM/地理位置/设备）
 → SessionEvent 追加（pageview/click/scroll/custom…）
 → 特殊类型：outbound_click / goal_conversion / events_children(回放) / heatmap_*
```

### 4.2 统计读取

```
StatisticsService::range() 统一入口
 → 全部查询带 website_id + [start,end] + type 复合索引
 → 按「维度」方法组织：pageviewsSeries/visitorsGrow/topPages/referrers/…
 → 返回纯数组，视图零查询（热数据另享 Cache）
 → AnalyticsFilters（§5.3）：country/browser/os/device… 任意维度过滤透传
```

### 4.3 支付流

```
用户选套餐 → PaymentController::process(processor 路由分发)
 → Services/Payment/{Gateway}Gateway::createPayment()
 → 网关回调 → WebhookPaymentController（验签）→ PaymentService::handlePaymentSuccess
 → 用户套餐变更 + WebhookService 外发 payment_success + 发票/邮件
```

## 5. 配置体系（三层）

| 层 | 位置 | 用途 | 变更方式 |
|----|------|------|----------|
| 环境层 | `.env` / `config/monit.php` | 基础设施（DB/缓存/像素参数） | 部署期 |
| 平台层 | `settings` 表 | 全部业务开关（30 组，含 branding） | 后台热更 |
| 用户层 | `users.preferences` / `plan_settings` | 个人偏好/套餐配额 | 用户中心 |

读取规范：**业务代码一律 `Settings::get('group.key')`，禁止直接 `config()`**；
后台保存走 `AdminSettings::update()`（自动校验 + `Settings::flush()` 双缓存失效）。

## 7. 二开实操场景

### 场景 A：新增统计维度「浏览器版本分布」

```php
// 1) app/Services/StatisticsService.php 新增方法
public function browserVersionSeries(): array
{
    return $this->sessionsQuery()                    // 复用统一的区间+过滤查询
        ->selectRaw('browser_name, count(*) as total')
        ->whereNotNull('browser_name')
        ->groupBy('browser_name')
        ->orderByDesc('total')
        ->limit(10)->get()->toArray();
}
// 2) StatsController@index 组装返回
// 3) resources/views/stats/browser-version.blade.php 渲染（复用 components/rank-panel）
// 4) lang/zh_CN.json + en.json 同键新增；路由 stats/{website}/browser-version
// 5) tests/Feature/YourTest.php 断言查询正确性
```

### 场景 B：新增采集事件 `video_play`

```php
// app/Services/PixelTracker.php handleAdvanced() switch 增加：
case 'video_play':
    $this->insertLightweightEvent('video_play', $data); // 复用轻量写入

// public/assets/pixel/monit.js 增加 monit('video_play', {...}) 透传
```

## 9. 部署要点

- 伪静态/HTTPS/缓存策略：`deploy/nginx/monit.conf`、`deploy/apache/monit.conf`（勿手写）
- 采集端点已在 Nginx 层关闭 access_log 并放行 CORS（高流量保护）
- 上线五件套：`migrate --force` / `storage:link` / `config:cache` / `route:cache` / `view:cache`
- Cron：`* * * * * php artisan schedule:run`
- 详细步骤：`public/docs/install.html`（或线上 /docs/install.html）

## 10. 代码注释规范

核心文件头部统一带「关联注释」块（M23 起为约定）：

```php
/**
 * 服务/控制器一句话职责（规格书 §章节）
 *
 * 关联：
 * - 上游：谁调用本类（Controller/Command/…）
 * - 下游：本类依赖什么（Model/Service/配置键）
 * - 设置：涉及 settings 组.键（后台哪个 tab 维护）
 */
```

修改代码时请同步维护该块；跨文件跳转优先看「关联」而非全文搜索。
